Agentic AI

A model, tools and a loop

An agent is a language model that asks for functions to be run and reads what they return, in a loop, until the task is done. The session covers how the loop works, what it costs, where it fails and what a bank puts around it.

The loop · Concept

Concept An agent is a model called in a loop. Each turn it either asks for a function to be run or gives the answer.

one task · every arrow into the model is a new model call

The model writes text

A tool call is a few lines of JSON in the reply. The model has no access to the function itself.

The code holds the permissions

The loop parses the text and chooses whether to run it. Access rights, limits and logging live here.

The loop needs a stop

A model can keep asking for tools. A step limit and a spending limit are set in code.

The loop · Mechanism

Mechanism One recorded run of Qwen2.5-1.5B-Instruct. The tool is described in the system message, the model replies with a call, the code runs it.

1 · the tool, as the model reads it (abridged)
{"name": "search", "description": "Search the bank's product guides and policies. Returns the two sections that best match the query. ...", "parameters": { "type": "object", "required": ["query"], "properties": {"query": { "type": "string", "description": "what to look for ..."}}}}
A name, a description and a typed list of arguments. The description is the only thing the model knows about the tool.
2 · the model writes a call
task What is the purchase rate on the Platinum Credit Card, as a percentage APR? model <tool_call> {"name": "search", "arguments": {"query": "Platinum Credit Card purchase rate"}} </tool_call>
The chat template tells the model to wrap a call in <tool_call> tags. The loop looks for those tags in the reply.
3 · the code runs it, the model reads the result
search("Platinum Credit Card purchase rate") [CC-02#1] Product guide: Platinum Credit Card, Rates: The purchase rate on the Platinum Credit Card is 19.9% APR. Taking cash on the Platinum Credit Card costs 2.5% of the amount, with a minimum of GBP 3. Interest on cash is charged from the day of the withdrawal. model ANSWER: 19.9%
The second reply has no tool call, so the loop ends. Two model calls for one figure.

The loop · Drawbacks

Drawbacks Four failures from the five recorded runs, each with the evidence and the change to the loop or the tools that addresses it.

failurein the recorded runchange
Answers from memoryAsked for the Premier cash machine limit, the model called no tool and replied ANSWER: 3000.0. The document says 900.Accept a figure only if it appears in a tool result of that run.
Searches for the wrong thingThe task is about the foreign currency fee. Both queries asked for the monthly fee.Narrow tools with typed arguments, such as get_fee(product, fee_type).
Uses results it has not seenSearches and the calculator were requested in one reply, so the expression was interest_free_overdraft_buffer(Standard) + interest_free_o...Run one call per reply. Return the error text to the model.
Does the arithmetic itselfAfter the calculator refused, the model replied ANSWER: 650. The figures it had retrieved give 50 + 500 + 1500 = 2,050.Check in code that the final number is one the calculator returned.
A small model. These runs use a 1.5-billion-weight model, chosen because it runs on a laptop. The four checks apply to a model of any size.
Every fix is code. None of the four changes asks the model to behave better. Each one is a check or a narrower interface outside it.

Cost Two pieces of arithmetic. Steps multiply their error rates, and every model call rereads the conversation so far.

Tokens read grow with the square of the steps. Call k reads the first call plus k − 1 results. Latency and the bill follow the tokens read.
Chain or agent · Concept

Concept Six designs, ordered by how much of the control flow is left to the model.

who decides what happens next

Workflow

The first four. Model calls sit inside a program whose branches a person wrote. Retrieval-augmented generation from the last session is one.

Agent

The last two. The program is the loop, and the path through the tools is different for each task.

Chain or agent · Example

Example From the last session: 37 questions that compare the products of a class. A fixed chain answers 100%; the same model, given every section and asked to compare, answers 41%.

correct answers on 37 comparison questions · measured in the LLMs in Depth notebook
the fixed chain
question Which account has the highest daily cash machine limit? step 1 the ontology lists the products of the class (code) step 2 one current section is fetched for each (code) step 3 the model reads one figure from each section (117 calls) step 4 max() or min() names the product (code)

Use a fixed chain when

the steps are the same for every task of the kind, as they are here. Each step has one small job and its own test.

Use an agent when

the steps depend on what earlier steps return: an investigation, a support case, a codebase. The path cannot be written down in advance.

Start with the chain. Move a step into the model’s hands only when the tasks need it.

Guardrails · Concept

Concept Tools are sorted by what a wrong call costs. The rule for each tier is enforced by the loop, outside the model.

three tiers of tools
the check the loop makes on every tool call
Instructions inside tool results. In the last session a sentence planted in a retrieved section was obeyed in 2% of 98 answers. In a chat that is one wrong reply. With a write tool it is a payment.
Least privilege. Each task gets the tools it needs and the agent acts with the access rights of the member of staff who started it.
Limits and a log. A cap on steps, on tokens and on the amount per action. Every call and result is stored, which gives the audit trail.
Guardrails · Test

Test An agent is tested like any other program that takes actions: on tasks with known outcomes, before and after every change.

  1. Write tasks with known answers. Include the four failures from the recorded runs and at least one task where the right action is to refuse.
  2. Score the outcome. Share of tasks solved, and share of tasks where a write tool was called without cause.
  3. Score the path. Was each tool call valid, was the right tool chosen, how many steps were used against the fewest needed.
  4. Record the cost. Model calls, tokens read and seconds for each solved task.
  5. Rerun the set when the prompt, a tool description or the model changes.

Summary

Summary The loop, its cost and its controls.

model calls for one figure2
recorded runs correct2 of 5
8 steps at 0.95 each66%
fixed chain, 37 comparisons100%
The loop. The model writes a tool call as text, the code runs it and appends the result, and the model is called again until it answers.
The cost. Error rates multiply across steps and every call rereads the conversation. Where the steps are known in advance, a fixed chain is cheaper and easier to test.
The controls. Tools in tiers, approval for anything that writes, limits on steps and amounts, a log of every call, and a task set that is rerun on every change.
